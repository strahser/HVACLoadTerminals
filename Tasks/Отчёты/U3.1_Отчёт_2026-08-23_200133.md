## Что было не так (факт по коду)

1. Координаты X/Y в таблицах размещений и HTML-тултипе показывались во внутренних
   единицах Revit (футы): `ToRows` выдавал `Math.Round(p.Position.X, 3)` без
   конвертации, HTML-тултип — `toFixed(2) + ' ft'`.
2. Колонка «RoomId» показывала внутренний Id помещения (`RoomName = p.RoomId`),
   а не «№. Имя»; колонки «Уровень» в таблице размещений не было.
3. k_ef в гридах и на OxyPlot-плане отображался по цвету системы, без визуализации
   порогов <0.6 / 0.6–0.9 / >0.9.
4. Тулбар ревит-стенда отставал от App: не было «Назначение», «v решётки»,
   «Сохранить/Загрузить проект», «HTML»; кнопки в StackPanel обрезались.
5. «Живой пересчёт» реально пересчитывал ВСЕ комнаты на каждый символ правки Q —
   комментарий «debounced» был лживым (полный `Calculate()` прямо в
   `PropertyChanged`-обработчике `HookLiveRecalc`).
6. Числовые поля молча клампились (`Math.Max(1, value)` в App) без сообщения —
   инженер не понимал, почему ввели другое значение.

## Что сделано

### 1. Координаты в мм (таблицы + OxyPlot + HTML)
- `src/Infrastructure/Presentation/SnapshotWorkspacePresenter.cs` — `ToRows`:
  `X = Math.Round(LengthUnitConverter.UnitsToMm(p.Position.X), 0)` (и Y) через
  существующий `LengthUnitConverter` (304.8 мм/фут).
- `src/Infrastructure/Visualization/HtmlSceneExporter.cs` — тултип:
  `'Координаты: (' + fmtMm(x) + ', ' + fmtMm(y) + ') мм'` и `'Расход: … м³/ч'`
  (функция `fmtMm(ft)` с `FT_TO_MM = 304.8`).
- `src/App/ViewModels/MainViewModel.cs` — OxyPlot-план на мм: оси «X, мм»/«Y, мм»,
  вершины контуров и подсветка сторон паттернов умножаются на
  `LengthUnitConverter.MmPerFoot`.

### 2. «№. Имя» + колонка «Уровень»
- `SnapshotWorkspacePresenter.ToRows` — `RoomName = $"{room.Number}. {room.Name}"`,
  `LevelName = room?.LevelName ?? ""`.
- Оба грида (App `src/App/MainWindow.xaml`, стенд `src/Revit/UI/SnapshotPlacementWindow.xaml`):
  заголовок «RoomId» → «Помещение», добавлена колонка «Уровень».

### 3. k_ef цветом по порогам <0.6 / 0.6–0.9 / >0.9
- `src/Infrastructure/Presentation/Rows.cs` — `PlacementRow.KefStatus`
  (`low`/`ok`/`high`/пусто).
- Оба грида — `ElementStyle` + `DataTrigger` по `KefStatus` (оранжевый #E67E22 /
  зелёный #1E8E3E / красный #D93025); подпись таблицы обновлена
  («0.6–0.9 норма»).
- `MainViewModel.PlotLevelCore` — ScatterSeries группируется по `KefStatus`
  (Отопление остаётся оранжевым, приборы без k_ef — синим), легенда
  «недогруз (<0.6) / норма (0.6–0.9) / перегруз (>0.9)».

### 4. Тулбар стенда — паритет с App
- `src/Revit/UI/SnapshotPlacementWindow.xaml` — StackPanel → WrapPanel (не обрезается),
  добавлены «Назначение» + «Применить к уровню», «v решётки», «💾 Сохранить проект»,
  «📂 Загрузить проект», «🌐 HTML»; тултипы приведены к App.
- `src/Revit/UI/SnapshotPlacementWindow.xaml.cs` — обработчики `ApplyPurpose_Click`,
  `SaveProject_Click`, `LoadProject_Click`, `ExportHtml_Click` (WebView2-хост из
  Infrastructure с fallback на файл+браузер); ErrorSink → статус-строка.

### 5. LiveRecalc debounce 300 мс
- `SnapshotWorkspacePresenter` — `ILiveRecalcScheduler` +
  `DispatcherTimerLiveRecalcScheduler` (UI-поток, безопасен для коллекций),
  `LiveRecalcDebounceMs = 300`, свойство `LiveRecalcScheduler` (в тестах — фейк).
- `HookLiveRecalc` теперь только `ScheduleLiveRecalc()` (Cancel + Schedule);
  `RunLiveRecalc` проверяет флажок `LiveRecalc`.

### 6. Валидация числовых полей с сообщением
- `SnapshotWorkspacePresenter` — `MinWindowLengthRatio` (0–1), `FixedSupplyCount` (≥1),
  `GrilleVelocityMs` (>0) валидируются с сообщением через `ErrorSink`; значение не
  меняется при невалидном вводе.
- `MainViewModel.FixedSupplyCount` — убран молчаливый `Math.Max(1, value)`.

### 7. Общий путь HTML-сцены
- `BuildPlacementResults()` переехал в presenter (был приватным в MainViewModel) —
  оба хоста строят HTML-сцену единообразно.

### 8. Тесты (+10, всего 108)

## Решения (grill)
- Единицы таблиц/плана/тултипа — мм через `LengthUnitConverter.UnitsToMm`
  (пороги k_ef из карточки: <0.6 / 0.6–0.9 / >0.9).
- Debounce 300 мс — `DispatcherTimerLiveRecalcScheduler` (UI-поток) + тестовый фейк.
- Паритет тулбара стенда — точный состав из App (без «Записать в модель» в App).
- Критерий «grep футов» трактован как «нет футов в ФОРМАТЕ ячеек»
  (заголовки/значения); внутренние футы-единицы Revit и комментарии не трогались.

## Открытые вопросы / ограничения
- Скриншот стенда снят в режиме без Revit API (handler=null) — тулбар тот же,
  кнопка «Записать в модель» активна только внутри Revit (по коду, как раньше).
- Скриншоты и лог сделаны вручную (UI-приложение), модель их не генерировала.
