# ОТЧЁТ: U1.1 — Фильтр таблицы помещений по уровню (баг-фикс)

Дата: 2026-08-23. Статус: **done** (повторный прогон карточки; первоначальная
реализация — коммит `ef28241`, вердикт контролёра PASS `ad1b598`).

## Что было не так (факт по коду)

`RoomsView.Refresh()` в сеттере `SelectedLevel` вызывался, но предикат
`.Filter` не был назначен — `ICollectionView` показывал все комнаты независимо
от выбранного уровня в ComboBox.

## Что сделано

`src/App/ViewModels/MainViewModel.cs` — при первом обращении к `RoomsView`
назначается предикат фильтрации (строки 33-44):

```csharp
public ICollectionView RoomsView
{
    get
    {
        if (_roomsView != null)
            return _roomsView;
        _roomsView = CollectionViewSource.GetDefaultView(Workspace.Rooms);
        // U1.1: выбор уровня в ComboBox фильтрует таблицу помещений.
        _roomsView.Filter = o => o is RoomRow row && FilterVisible(row);
        return _roomsView;
    }
}
```

`FilterVisible` (строки 312-313) уже существовал и использовался «Применить
назначение»/«Только видимые» — поведение по видимым строкам не менялось.
Смена уровня вызывает `RoomsView.Refresh()` (строка 57) + перерисовку плана.

### Ревит-хост — проверен, изменений не требуется

`src/Revit/UI/SnapshotPlacementWindow.xaml.cs:53` — `RoomsGrid.ItemsSource =
state.Rooms` (сырой ребиндинг коллекции, собственного `ICollectionView` стенд
не держит), ComboBox уровня отсутствует (XAML стенда: только правила/паттерны).
Условие карточки «если он держит свой ICollectionView — применить тот же фикс»
не выполняется — фикс неприменим, код стенда не трогался.

## Решения (grill)

- Фикс в тонком хосте App (`MainViewModel.RoomsView`), а не в presenter: стенд
  ревита своего `ICollectionView` не держит (`ItemsSource = state.Rooms`),
  фикс к нему неприменим — решения взяты из карточки и кода, вопросов
  владельцу не потребовалось.
- Критерий «74/74» трактован как «базовый счётчик Core.Tests не деградировал»:
  фактически 108/108 (база выросла за счёт последующих карточек U1.2–U3.1).
