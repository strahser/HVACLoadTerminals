**Исполнитель**: интерактивная сессия агента.

## Что сделано

1. **`Core/Services/SnapshotPlacementEngine.cs`**:
   - `Build(...)` += опциональный `systemsByRoom : IReadOnlyDictionary<string,
     IReadOnlyList<HVACSystem>>` (существующие вызовы LocalRunner и
     ImportSnapshotPlacementCommand совместимы без правок);
   - `ResolveSystems`: пользовательские системы комнаты, если заданы и непусты;
     иначе автодефолт П1/В1 из оценки (`EstimatedRoomLoads`) — прежнее поведение;
   - цикл размещения по каждой системе: Supply/Exhaust →
     `CeilingPlacementService(flow=s.FlowRate, systemName=s.Name)`;
     прочие типы/нулевой расход → warning «система пропущена».
2. **`Infrastructure/Presentation/SnapshotWorkspacePresenter.cs` — `Calculate()`**:
   агрегатные вызовы «Приток»/«Вытяжка» заменены перебором `row.Systems`
   (после `EnsureDefaultSystems`): per-system k_ef (`StoreKef` по ключу
   room|systemName), PatternEdges с именем системы, решётки C1.5 считаются на
   каждую вытяжную систему отдельно (строка Warning собирает их списком);
   `IsIncluded=false` у системы исключает её из расчёта.
   `WorkspaceState.SupplyCount/ExhaustCount/HeatingCount` теперь считают по
   `Device.SystemType`, а не по хардкод-именам систем.
3. **Обновлены тесты под новую семантику имён** (автодефолт теперь П1/В1, а не
   «Приток»/«Вытяжка» — это и есть цель S2.1):
   `SnapshotWorkspacePresenterTests` (рёбра паттернов → П1/В1),
   `OfflineCatalogTests` (×2 → П1), `CalculatedFlowTests` (×2 → П1).
4. **Новые тесты** `Core.Tests/SystemsEngineTests.cs` (5):
   две приточные системы на прямоугольнике (П1=2 точки, П2=1, все внутри контура,
   ни одна точка П1 не совпадает с П2, CalculatedFlow по каждой системе);
   отсутствие словаря → дефолт из оценки; пустой список в словаре → дефолт;
   presenter: пользовательские П1/П2 доходят до placements и k_ef>0;
   исключённая система не размещается.
