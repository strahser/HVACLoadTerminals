# S1.1 — Отчёт: список именованных систем в строке комнаты + round-trip проекта (2026-08-24 11:45)

**Карточка**: S1.1 плана `2026-08-24_named-systems-and-revit-conversion.md`
**Исполнитель**: интерактивная сессия агента (цикл из промпта владельца; раннер не задействован).

## Что сделано

1. **`Infrastructure/Presentation/Rows.cs`**:
   - новый класс `SystemRow` {Name, Type (HVACSystemType), FlowM3h, IsIncluded}
     с INPC (задел под редактор S1.2);
   - `RoomRow.Systems : List<SystemRow>` (инициализируется пустым списком).
2. **`Infrastructure/Presentation/SnapshotWorkspacePresenter.cs`**:
   - `EnsureDefaultSystems(RoomRow)` — пустой список → автодефолт «П1»/«В1» из
     оценённых `row.Supply`/`row.Exhaust`; непустой пользовательский список не
     трогается; вызывается в начале обработки каждой включённой комнаты `Calculate()`;
   - `GetSystemErrors(RoomRow)` — валидация: пустое имя, дубликат имени
     (case-insensitive внутри комнаты), расход ≤ 0;
     `Calculate()` рапортует ошибки через ErrorSink, расчёт не прерывает.
3. **Round-trip**: `ProjectDto.Rooms` сериализует `Systems` автоматически
   (StringEnumConverter даёт читаемые имена типов); legacy-файлы без поля Systems
   десериализуются в пустые списки → при первом расчёте строится автодефолт.
4. **Тесты** `Core.Tests/NamedSystemsTests.cs` (5 новых):
   round-trip трёх систем (П1=120/П2=80/В1=200), автодефолт из оценки,
   legacy-проект без систем (рукописный JSON) грузится и рассчитывается,
   пользовательские системы не перезаписываются, валидация ошибок.

## Открытые вопросы

1. Автодефолт строится только для включённых комнат в момент Calculate —
   строки выключенных комнат остаются с пустым списком до их расчёта. Для UI S1.2,
   возможно, понадобится строить дефолт сразу при открытии снимка (решить в S1.2).
2. Тип `SystemRow.Type` использует enum `HVACSystemType` (Supply/Exhaust сейчас;
   Heating/FanCoil игнорируются движком) — расширение «Кондиционирование»
   (открытый вопрос №2 ТЗ) ляжет сюда же.
