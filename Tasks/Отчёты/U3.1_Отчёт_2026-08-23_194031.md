1. Координаты X/Y в таблицах размещений и HTML-тултипе показывались во внутренних

   `Math.Round(p.Position.X, 3)` без конвертации; HTML-тултип — `toFixed(2) + ' ft'`).

   а не «№. Имя»; колонки «Уровень» в таблице размещений не было вообще.
3. k_ef в гридах и на OxyPlot-плане отображался обычным цветом (по системе),
   без визуализации порогов <0.6 / 0.6–0.9 / >0.9.
4. Тулбар ревит-стенда отставал от App: не было «Назначение», «v решётки»,
   «Сохранить/Загрузить проект», «HTML»; кнопки в StackPanel обрезались.
5. «Живой пересчёт» реально пересчитывал ВСЕ комнаты на каждый символ правки Q —
   комментарий «debounced» был лживым (полный `Calculate()` прямо в
   `PropertyChanged`-обработчике).
6. Числовые поля молча клампились (`Math.Max(1, value)` в App) без сообщения —
   инженер не понимал, почему ввели другое значение.

## Что сделано

### 1. Координаты в мм (таблицы + OxyPlot + HTML)
- `src/Infrastructure/Presentation/SnapshotWorkspacePresenter.cs` — `ToRows`:
  `X = Math.Round(LengthUnitConverter.UnitsToMm(p.Position.X), 0)` (и Y) —
  конвертация через существующий `LengthUnitConverter` (304.8 мм/фут).
- `src/Infrastructure/Visualization/HtmlSceneExporter.cs` — тултип теперь:
  `'Координаты: (' + fmtMm(x) + ', ' + fmtMm(y) + ') мм'` + `'Расход: … м³/ч'`
  (функция `fmtMm(ft)` с константой `FT_TO_MM = 304.8`).
- `src/App/ViewModels/MainViewModel.cs` — OxyPlot-план переведён на мм:
  оси «X, мм»/«Y, мм», вершины контуров и подсветка сторон паттернов
  умножаются на `LengthUnitConverter.MmPerFoot`.

### 2. «№. Имя» + колонка «Уровень»

  заголовок «RoomId» → «Помещение», добавлена колонка «Уровень».

### 3. k_ef цветом по порогам <0.6 / 0.6–0.9 / >0.9

### Сценарий «правка Q → через 300 мс один пересчёт» (лог таймингов)
Файл: `Tasks\Отчёты\U3.1_артефакты\U3.1_liverecalc_timing.log`:
```
[  0 мс] правка: Q := 500 (символ 1) → строка: Q=500 Вт, приток=540 м³/ч
[  0 мс] правка: Q := 505 (символ 2) → строка: Q=505 Вт, приток=540 м³/ч
[105 мс] правка: приток := 120 → строка: Q=505 Вт, приток=120 м³/ч
[583 мс] контрольный таймер 300 мс (запущен с последней правкой): фактическая задержка 478 мс
[583 мс] ПЕРЕСЧЁТ #1 (приборов: 583)
ИТОГ: PASS — 3 события правки → ровно ОДИН пересчёт, 483 мс после последней правки (пауза 300 мс)
```
Пояснение: коалесинг правок подтверждён (3 события → ровно один пересчёт).
Контрольный «голый» DispatcherTimer(300 мс), запущенный в момент последней
правки, срабатывает в тот же отсчёт (583 мс), что и пересчёт, — планировщик
не добавляет накладных расходов, а измеренные ~480 мс — гранулярность
DispatcherTimer при фоновой прокачке очереди в харнессе. Параметр паузы
300 мс закреплён юнит-тестом `LiveRecalc_Debounce_Runs_Calculate_Once_Per_Burst`
(`fake.LastDelay == TimeSpan.FromMilliseconds(300)`).

## Решения (grill)
- Единицы таблиц/плана/тултипа — мм через `LengthUnitConverter.UnitsToMm`
  (пороги k_ef из карточки: <0.6 / 0.6–0.9 / >0.9).
- Debounce 300 мс — `DispatcherTimerLiveRecalcScheduler` (UI-поток) + тестовый фейк.
- Паритет тулбара стенда — точный состав из App (без «Записать в модель» в App).
- Критерий «grep футов» трактован как «нет футов в ФОРМАТЕ ячеек» (заголовки/значения),
  внутренние футы-единицы Revit и комментарии не трогались.
