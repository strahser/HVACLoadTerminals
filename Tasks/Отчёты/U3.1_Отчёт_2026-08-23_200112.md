# ОТЧЁТ: U3.1 — Паритет и удобство хостов App ↔ ревит-стенд

Дата: 2026-08-23. Статус: done.
Источник: карточка U3.1 плана `2026-08-23_ui-usability-critique-fixes.md`.

## Решения (grill)
- Блокирующих вопросов не потребовалось: все 6 пунктов карточки однозначны по коду
  (пороги k_ef <0.6 / 0.6–0.9 / >0.9 и пауза debounce 300 мс заданы в карточке).
- ASSUMPTION: паритет тулбара стенда ограничен общими контролами расчёта/проекта/HTML;
  стенд не получает специфичных для App кнопок фильтра уровня («Включить уровень»,
  «Только видимые») и «Каталог приборов», т.к. на стенде нет фильтра уровня и каталога
  (карточка требует только: правило вытяжки, v решётки, назначение, сохранить/загрузить
  проект, HTML — все добавлены).

## Что было не так (факты по коду)
1. Координаты X/Y в таблицах размещений обоих хостов и HTML-тултипе показывались в футах
   (`Math.Round(p.Position.X, 3)` в `ToRows`; `'Pos: (... ) ft'` в HtmlSceneExporter).
2. Колонка «RoomId» в таблице размещений показывала внутренний Id помещения (`p.RoomId`),
   уровня не было вовсе.
3. k_ef показывался числом без цветовой индикации (пороги недогруз/норма/перегруз).
4. Тулбар ревит-стенда отставал от App: не было назначения, v решётки, сохранить/загрузить
   проект и HTML; контейнер тулбара — StackPanel (кнопки обрезались).
5. LiveRecalc пересчитывал ВСЕ комнаты на каждый символ правки Q/расхода
   (`Calculate()` прямо в PropertyChanged), хотя комментарий обещал debounce.
6. Числовые поля `FixedSupplyCount` (App) и др. молча клампились через `Math.Max(1, value)`
   без сообщения пользователю.

## Что сделано (пути файлов)
1. **Единицы в мм** — `src/Infrastructure/Presentation/SnapshotWorkspacePresenter.cs`
   (`ToRows`: `LengthUnitConverter.UnitsToMm(...)`, округление до целых) и
   `src/Infrastructure/Visualization/HtmlSceneExporter.cs` (тултип: `fmtMm()` =
   футы×304.8, «Расход: … м³/ч», «Координаты: (…, …) мм»). Оси плана и координаты
   помещений на OxyPlot-плане переведены в мм (`src/App/ViewModels/MainViewModel.cs`:
   `mmPerFoot = LengthUnitConverter.MmPerFoot`, заголовки осей «X, мм»/«Y, мм»).
2. **«№. Имя» + уровень** — `Rows.cs` (новое свойство `LevelName`), `ToRows`:
   `RoomName = $"{room.Number}. {room.Name}"`, `LevelName = room.LevelName`.
   Заголовки обоих гридов: «Помещение», «Уровень» (`src/App/MainWindow.xaml`,
   `src/Revit/UI/SnapshotPlacementWindow.xaml`).
3. **k_ef цветом** — `Rows.cs`: свойство `KefStatus` (low/ok/high, KEf≤0 → «»);
   DataTrigger-стили на `KefStatus` в обоих XAML (оранжевый/зелёный/красный);
   на плане `MainViewModel.PlotLevelCore`: приборы сгруппированы по k_ef и окрашены
   (недогруз оранжевый, норма зелёный, перегруз красный, отопление — оранжевый,
   без k_ef — серый/синий), легенда подписана порогами.
4. **Тулбар стенда** — `src/Revit/UI/SnapshotPlacementWindow.xaml/.cs`:
   StackPanel→WrapPanel; добавлены «Назначение» + «Применить к уровню»,
   «v решётки», «💾 Сохранить проект», «📂 Загрузить проект», «🌐 HTML»
   (общий WebView2-хост Infrastructure с fallback на файл+браузер), тултипы.
   «Записать в модель» срабатывает только при наличии API-контекста
   (`handler/externalEvent == null` → сообщение в статусе, без падения).
5. **LiveRecalc debounce 300 мс** — `SnapshotWorkspacePresenter.cs`:
   интерфейс `ILiveRecalcScheduler` + `DispatcherTimerLiveRecalcScheduler`
   (тик в UI-потоке), свойство `LiveRecalcDebounceMs = 300`; правки Q/притока/вытяжки
   коалесируются через `ScheduleLiveRecalc()` → один `Calculate()` после ПОСЛЕДНЕЙ
   правки серии. Тесты подменяют планировщик фейком.
6. **Валидация числовых полей** — `SnapshotWorkspacePresenter.cs`: `MinWindowLengthRatio`
   (0–1), `FixedSupplyCount` (≥1), `GrilleVelocityMs` (>0) валидируются через `ErrorSink`
   с сообщением; невалидное значение не применяется. Убран `Math.Max(1, value)`
   из `src/App/ViewModels/MainViewModel.cs`.


Q в таблицу помещений — пересчёт только после паузы 300 мс (см. лог таймингов).
