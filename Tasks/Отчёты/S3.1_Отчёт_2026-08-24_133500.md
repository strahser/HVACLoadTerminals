## Что сделано

1. **Новый сервис** `src/Revit/Services/RevitSystemAssigner.cs`:
   - `Assign(pairs)` принимает пары «placement → созданный FamilyInstance»;
   - для каждого прибора: первый коннектор `MEPModel.ConnectorManager.Connectors`;
     нет коннектора → warning + записаны только параметры, система пропущена
     (`SkippedNoConnector`);
   - поиск MechanicalSystem по точному имени, иначе `MechanicalSystem.Create(doc,
     typeId, name)` (кэш по имени за прогон — дублей нет; GetExistingSystem
     переиспользует существующую);
   - тип системы: класс прибора Supply→«ADSK_Приточный воздух» /
     Exhaust→«ADSK_Отработанный воздух»; fallback — DuctSystemType коннектора
     (SupplyAir/ExhaustAir), затем первый доступный MechanicalSystemType;
   - `ConnectorSet.Insert(connector)` → `system.Add`;
   - расчётный расход: `RBS_DUCT_FLOW_PARAM` во внутренних единицах
     (`UnitUtils.ConvertToInternalUnits(м³/ч)`) + `LookupParameter("ADSK_Расход
     воздуха")`; инстанс-параметр «ИмяСистемы», если есть;
   - лог назначений `SystemAssignmentReport`: на систему — число приборов,
     Σрасход, флаг «создана», warnings; `FormatSummary()` для сводки диалога.
2. **RevitDevicePlacer**:
   - `PlaceDevicesInTransaction(...)` += опциональный `instanceCreated`
     callback (placement, instance) — источник пар для ассайнера;
   - **баг данных из ревью-блока исправлен**: `ApplyAirflow` теперь пишет в
     параметр расхода РАСЧЁТНЫЙ `CalculatedFlowM3h`, а не паспортный
     MaxFlowRate типоразмера (0 → legacy-поведение).
3. Интеграция команд записи — карточка S3.2 (следующая); критерий 1
   (интеграционный Revit-тест) исполняется в S4.1 на HvackFinal.rvt.

## Открытые вопросы

1. Приборы отопления (радиаторы) без воздушных коннекторов всегда попадут в
   «SkippedNoConnector» с warning'ом — соответствует предложению ТЗ
   (открытый вопрос №3: параметры + warning).

   маркерного пространства поведение стандартное (исключение → warning строки).
